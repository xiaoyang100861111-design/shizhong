# 测试数据

适中自带一个**测试数据生成器**（`server/Shizhong.Api/Modules/Seed/`），能在几十秒内造出一个"已经运营了 90 天"的平台：约 2,000 名会员、30 个代理、每个内置角色的后台账号、8,000 笔订单、4 万多笔礼物流水、3,000 场直播、几万条聊天、充值提现和完整的资金流水。所有人物、手机号、邮箱、地址、交易哈希都是虚构的。

数据是**确定的**（固定随机种子，同一个种子、同一天运行结果一样），**可重复运行**（已生成过会跳过，除非要求重置），并且**只删自己生成的数据**——真实注册的会员、商家和后台账号不会被动到。

## 怎么生成 / 清除

### 方式一：命令行

先编译 API（`dotnet build server`），然后在 `server/Shizhong.Api` 目录下：

```bash
# 生成（先跑迁移和初始化，生成完做一致性检查后退出）
dotnet bin/Debug/net8.0/Shizhong.Api.dll --seed

# 先清掉上次生成的，再重新生成
dotnet bin/Debug/net8.0/Shizhong.Api.dll --seed --reset

# 数据量减半 / 加倍（会员、订单、直播等按比例缩放）
dotnet bin/Debug/net8.0/Shizhong.Api.dll --seed --reset --scale 0.5

# 换一个随机种子（默认 20260929）
dotnet bin/Debug/net8.0/Shizhong.Api.dll --seed --reset --seed-random 42

# 只清除生成的数据
dotnet bin/Debug/net8.0/Shizhong.Api.dll --seed-clear

# 只做一致性检查（有问题时退出码为 2）
dotnet bin/Debug/net8.0/Shizhong.Api.dll --seed-verify
```

连接哪个数据库由 `appsettings*.json` 决定（和正常启动一样）。建议用单独的库，例如在 `appsettings.Local.json` 里把 `Database` 改成 `shizhong_seed`。

默认规模在开发机上大约 **26 秒生成、45 秒（含清除和检查）**，约 72 万行。

### 方式二：后台页面

**系统管理 › 测试数据**（`/admin/system/seed`），只有超级管理员能看到（权限 `system.seed`）。

- 显示各类数据的数量、上一次运行的结果、测试账号和密码；
- **生成测试数据**：可选规模和"先清除再生成"，在后台运行，页面显示进度；
- **清除测试数据**：只删生成的数据；
- **一致性检查**：跑下面列出的全部检查并显示结果。

配置项 `seed.enabled`（系统配置 › seed，默认开启）关掉后，页面只能查看，不能生成或清除。**正式环境请关闭。**

## 生成了什么

时间跨度为**最近 90 天**（马来西亚时间），有增长趋势（前期约为后期的 70%）、工作日/周末差异、一天里的作息（饭点、晚上高峰）和几个活动日高峰（8.8、国庆 8.31、9.9、马来西亚日 9.16、9.25 中秋）。

- **会员**：华人（中文名或拼音英文名）、马来人、印度人、英文名、网名混合；+60 手机号、邮箱；城市为吉隆坡、八打灵再也、槟城、新山、马六甲、怡保及其真实区域；头像来自 `assets/avatars`；按语言写的个人简介、兴趣；注册平台 web / android / ios；约 40% 在 90 天之前注册；有少量被封禁的账号（附带举报）；约 130 个主播。
- **代理与商家**：两级代理，带邀请码和下级会员；约 72% 的商家归属到同城代理；商家入驻申请（通过 / 驳回 / 待审）。
- **商城**：8,000 笔订单覆盖所有流程和状态（待确认、待服务、进行中、已完成、已取消、退款 / 部分退款），费用、优惠券、订单事件、商家沟通；约 5,000 条评价；购物车、收货地址、收藏、搜索记录；每周商家结算单。
- **社交**：约 1,500 条动态、6,000 条评论、点赞；2 万条关注、访客记录、好友申请、黑名单；6,000 个群成员关系。
- **聊天**：约 3 万条消息——一对一、群聊、客服会话（有客服回复）、商家咨询；图片消息；红包、转账（领取、退回、过期）；语音通话记录。
- **直播**：3,000 场直播（评论、点赞、观众）、4 万多笔礼物流水、主播收益（已释放 / 冻结中）、粉丝团；2,000 次一对一视频通话（按分钟计费）；VIP 成长值来自送礼。
- **资金**：加密货币充值（所有币种和网络，各种状态：已入账、确认中、低于最低额、无法识别、已关闭、需人工处理）——**交易哈希和地址都是格式正确但虚构的，备注里标着"测试数据（虚构交易）"**；线下充值（通过 / 驳回 / 取消 / 待审）；约 300 笔提现（余额提现和收益提现，各种状态）；代理佣金；人工调账。
- **成长**：每日签到、任务奖励、欢迎礼包、优惠券。
- **运营**：通知、约 500 个工单（举报、反馈、售后）及回复、后台操作日志、登录记录。

### 金额是对得上的

余额只通过资金流水变化，生成器按时间顺序"真正地"跑了一遍所有的钱：付款前余额不够会先充值，送礼前金豆不够会先兑换。生成后会跑下面这些检查（命令行和后台页面都能看到结果）：

- 余额 + 冻结 = RM 流水合计；金豆、收益余额 = 各自流水合计；没有负余额；
- 冻结金额 = 待审核的余额提现；冻结中的主播收益 = 未释放的收益记录；已释放收益都有入账流水；
- 订单：合计 = 小计 + 费用、应付 = 合计 − 优惠、小计 = 明细合计；支付 / 退款流水与订单一致；优惠券、结算单金额一致；
- 服务销量 / 评价数 / 评分、动态点赞数 / 评论数、直播场次统计与记录一致；
- 红包 / 转账的领取 + 退回 = 金额；直播和通话的主播收益 = 金豆价值 × 分成；通话费用 = 分钟 × 单价；
- VIP 成长值 = 直播与通话送礼金豆；粉丝团积分 = 入团后送出的礼物；礼物库存 = 购买 + 收到 − 送出；
- 已入账的加密货币 / 线下充值都有流水；已打款的提现都有扣款流水；代理佣金 = 充值 × 比例；签到奖励都有流水。

## 清除时做了什么

- 生成的每一行带自增 Id 的数据都登记在 `dbo.SeedKeys`（表名 + Id）里，清除时按登记删除，再删掉所有引用生成会员的数据（关注、点赞、消息、群成员等）；
- 商家的代理归属恢复为生成前的值；
- 演示账号：它自己的真实数据保留，生成器给它加的订单、聊天、礼物等删除，余额、金豆、VIP 按剩下的流水重算，注册时间恢复；
- 运营人物（persona）的礼物库存按剩余记录重建，服务、动态等的计数重新统计；
- 生成器打开过的配置（`agent.commissionEnabled`，如果之前没设置过）恢复。

每次运行都记录在 `dbo.SeedRuns`（迁移 `server/db/migrations/0900_seed.sql`）。如果上一次生成中途失败，下一次生成会自动先清除。
