## 2. 网页 + 安卓 + 苹果只维护一套系统：能做到

**方案：一套后端 + 一套前端 + Capacitor 打包 App。**

```
            ┌──────── 同一套 H5 前端代码（现有代码）────────┐
            │                 │                    │
        浏览器网页        安卓 App（Google Play）   苹果 App（App Store）
                          └── Capacitor 打包，调用原生能力 ──┘
            │                 │                    │
            └──────── 同一个 ASP.NET Core API + SQL Server ──┘
                              管理后台 /admin
```

- **为什么选 Capacitor**：现有前端是纯 H5（没有框架、没有构建），Capacitor 可以直接把它装进 App 壳，**不用重写**。以后改功能只改一处，网页和两个 App 同时更新。
  - 如果换 Flutter / React Native，就要把 2.4 万行前端全部重写，等于维护两套前端，不符合你"只维护一套"的要求。
- **App 里能用的原生能力**：推送通知、相机/相册、麦克风、定位、分享、扫码、生物识别登录、深链。
- **本期要为 App 做的准备**（写后端时一起做，避免以后返工）：
  1. 登录同时支持 Cookie（网页）和 Token（App）。
  2. 接口地址可配置（App 里不是同域）。
  3. 推送通知预留设备 Token 表。
  4. 后台可配"App 最低版本 / 强制更新提示"。
- **上架的硬性规定（很重要，影响设计）**：
  - 苹果和谷歌都要求：**App 里购买虚拟物品（金豆、礼物、VIP、装扮）必须走它们的内购**，平台抽成 15%–30%。
    - 实物商品和线下服务（保洁、外卖、鲜花、接机）**可以**用自己的支付。
    - 所以金豆充值要预留"内购"渠道，后台可按平台（网页 / 安卓 / 苹果）配置不同的充值包价格。
  - 苹果要求 App 必须提供**App 内注销账号**（原型里已有"删除账号"，会做成真实功能）。
  - 有用户发布内容和聊天的 App，必须有**举报、拉黑、内容审核**（已在需求里）。
  - 直播、一对一视频类 App 审核较严，需要年龄限制（原型已有"年满 18"勾选）和内容审核机制。
- **App 打包本身不在本期**：本期先把后端和网页做完，并在前端预留好 Capacitor 接入点。打包和上架需要苹果开发者账号（USD 99/年）和谷歌开发者账号（USD 25 一次性）。

## 3. 总体架构

- 服务端同时托管：用户端网页 `/`、管理后台 `/admin`、用户接口 `/api/*`、后台接口 `/api/admin/*`、实时通道 `/hubs/*`。
- 后台任务：订单自动流转、红包 24 小时退回、优惠券过期、通知推送、统计汇总。
- **所有写死的参数 → 配置表**，前端启动时拉取；后台改完立即生效，每项都有"恢复默认"。
- 金额按"分"存 BIGINT，金豆 BIGINT，时间 UTC，文本 NVARCHAR（支持中文）。
- **钱包和金豆余额只由流水驱动**：每一笔增减都有流水记录，余额可对账。
- 保留"离线演示模式"：双击 `index.html` 打开时，前端仍按原型的本地模拟运行。

### 4.12 语音 / 视频（Cloudflare Realtime 无服务器 SFU）
- **用在哪**：
  - 聊天里的语音通话、视频通话（单聊）。
  - 一对一视频（按分钟计费）。

- **工作方式**：
  - 浏览器/App 用 WebRTC 直接连 Cloudflare 的全球节点，音视频不经过你的服务器，你的服务器只负责"信令"（谁呼叫谁、创建会话、鉴权、计费）。
  - 服务器调用 Cloudflare API 创建会话，需要 **App ID + App Token（密钥）**。
  - 网络差或有防火墙时，走 Cloudflare TURN 中继（可选，需要 TURN 密钥）。
- **后端**：通话/直播会话表、呼叫信令（SignalR：振铃、接听、拒接、超时、挂断）、通话记录、直播状态、一对一计费计时（以服务器时间为准）。
- **可配**：App ID、App Token、TURN 密钥；视频清晰度上限（默认 720p）、单场直播最长时长、无人接听超时（默认 30 秒；一对一 12 秒）、功能开关（通话 / 一对一 / 直播可以分别关闭）。
- **说明**：
  - Cloudflare Realtime 按流量计费（每月有免费额度），直播观众越多流量越大，费用在你的 Cloudflare 账户里结算。
  - 摄像头和麦克风必须在 **HTTPS** 下才能用（Cloudflare CDN 解决）。

### 4.13 加密货币收款
- **支持的币种和链**（默认，后台可增减）：

  | 币种 | ETH 链（ERC-20） | BSC 链（BEP-20） | 比特币链 |
  |---|---|---|---|
  | USDT | ✅ | ✅ | — |
  | USDC | ✅ | ✅ | — |
  | ETH | ✅（原生币） | — | — |
  | BTC | — | — | ✅（原生） |

  如还需要 **TRON 链（TRC-20 USDT）**，见第 8 节。
- **用户端流程**：
  1. 选择币种和链，可选输入要充值的 RM 金额（显示约需多少币）。
  2. 页面显示**该用户专属的收款地址** + 二维码 + 复制按钮 + 注意事项（只能转对应链、最低金额）。
  3. 用户从自己的钱包转账。
  4. 系统自动检测到账 → 显示"确认中 (n/12)" → 达到确认数后自动入账，发通知。
  5. 充值记录页可查看每笔的交易哈希、状态。
- **地址生成**：
  - 后台配置钱包种子，系统按 **HD 钱包标准（BIP32/44/84）** 给每个用户推导一个固定地址（ETH 和 BSC 共用同一个地址）。
  - **安全建议（重要）**：后台填**扩展公钥（xpub）**而不是助记词。xpub 能生成全部收款地址，但**不能转走钱**；即使服务器被入侵，资金也安全。助记词只保存在你自己的离线钱包里，用它就能看到并转走所有地址里的钱。见第 8 节。
- **到账检测**：后台任务定时查询区块链（通过公开区块链接口，如 Etherscan / BscScan / 比特币区块浏览器 API，后台填接口密钥），识别转入的交易并入账；防重复入账。
- **汇率**：
  - 默认自动获取市场价（USDT/USDC ≈ 1 美元，ETH/BTC 实时价）再按美元兑 RM 换算。
  - 后台可设"固定汇率"或"加点/手续费"，入账时锁定当时汇率并记录。
- **资金归集**：币会分散在每个用户的地址里，需要定期把币转到你的总钱包。用 xpub 方案时，归集由你用自己的钱包（持有助记词）操作；后台提供"各地址余额汇总"和导出，方便你归集。
- **后台**：充值记录（地址、链、币种、金额、哈希、确认数、汇率、入账 RM、状态）、异常处理（转错链、金额低于最低值、未识别）、手动补单、各地址余额、链和币种开关、最低充值金额、所需确认数。
- **可配（默认）**：最低充值 10 USDT/USDC、0.005 ETH、0.0002 BTC；确认数 ETH 12、BSC 15、BTC 2；汇率来源自动；手续费 0%。
- **提现**：本期用户提现仍为人工审核，**财务线下打款**（可以打加密货币到用户填写的地址，由财务在后台标记完成并填交易哈希）。
