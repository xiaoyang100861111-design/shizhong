# 适中 Shizhong · 后端 + 管理后台需求整理（v3 草案）

> 状态：**需求确认中，尚未写代码**。本文基于对现有前端约 2.4 万行代码的逐模块梳理（2026-09-29）。
> 目标：前端所有功能改为连接真实数据库 `Shizhong`（SQL Server，47.86.234.123），
> 前端写死的业务参数全部改为后台可配置（默认值 = 现在代码里的值），并提供一个完整的管理后台。

---

## 0. 现状与环境检查结论

| 项 | 结论 |
|---|---|
| 前端 | 纯静态 H5，无后端；所有数据存在浏览器 localStorage / IndexedDB；支付、短信、商家、聊天对方、直播观众全部是本地模拟 |
| 已有后端规划 | `docs/BACKEND.md`：ASP.NET Core 8 + Dapper + SQL Server，同域托管前端，`/api/*` |
| 数据库连通性 | **当前云端开发环境连不上**：47.86.234.123 被环境网络策略拦截（403 host_not_allowed），1433 端口不通；仓库里也没有数据库账号密码（按文档在 `E:/python/sz-secrets/`，只在你本机） |
| 开发工具 | .NET 8 SDK 可通过 apt 安装；NuGet、npm 可访问；微软镜像仓库可访问（可在本地起一个 SQL Server 容器做开发和自动化测试） |

## 1. 总体架构

```
浏览器 H5（现有前端，改为调 API）   管理后台 /admin（新建）
            │                                 │
            └──────── ASP.NET Core 8 API ─────┘   /api/*（用户端）  /api/admin/*（后台）
                         │  后台任务：订单自动流转、红包24h退回、优惠券过期、通知推送
                         │  实时：SignalR（聊天、直播评论/礼物、1对1 通话信令、在线状态）
                         ▼
                 SQL Server  Shizhong（迁移脚本 + 种子数据）
```

- 用户端保留"离线演示模式"：file:// 打开时照旧运行本地模拟（已有约定）。
- **所有写死的参数 → `SystemConfig` 配置表**，前端启动时 `GET /api/config` 拉取；后台改完即时生效（带缓存刷新）。
- 所有金额以"分"存储（BIGINT），金豆 BIGINT；时间 UTC；文本 NVARCHAR（中文）。
- 第三方能力（短信、邮件、支付网关、OAuth、推流/RTC）做成**可插拔接口**：默认"模拟实现"，后台可切换为真实服务商并填写密钥。

## 2. 用户端功能需求（前端全部功能 → 后端接口）

> 每个模块：用户能做什么 / 后端要实现什么 / 需要后台可配的参数（括号内为默认值）。

### 2.1 账号与登录（auth.js）
- 功能：欢迎页、手机号验证码注册/登录（16 个国家区号）、邮箱注册/密码登录、忘记密码、第三方登录（Google/Apple/Facebook）、演示账号、游客浏览、资料设置（头像、昵称、城市、语言、兴趣）、多账号切换、退出、修改密码、删除账号（PDPA）。
- 后端：用户表、BCrypt 密码、会话 token（HttpOnly Cookie）、OTP 生成与校验（哈希存储）、登录失败限流、唯一 8 位 displayId 分配、同意书与营销授权留存、账号注销与数据导出。
- 可配：OTP 有效期（5 分钟）、重发间隔（60 秒）、最多尝试（5 次）；密码错误锁定（5 次/30 秒）；密码规则（8–64 位含字母数字）；昵称长度（20）；头像大小（40KB/256px）；国家区号列表；注册城市（吉隆坡/八打灵再也/槟城/新山/马六甲/怡保）；兴趣标签（14 个）；启用的第三方登录；条款与隐私政策正文；演示模式开关（是否在页面显示验证码）。

### 2.2 首页 / 服务目录 / 搜索（catalog.js）
- 功能：城市切换、购物车入口、通知铃铛、分类宫格（10 个 + 更多 4 个）、Banner 与活动页、推荐/附近/好评/特惠筛选、分类页（分类内搜索、城市、5 种排序）、全部分类、服务详情（亮点、包含/不含、FAQ、评价、商家）、收藏、分享深链、全局搜索（服务/消息/人/群/动态）、搜索历史、热门搜索词。
- 后端：分类表、服务/商品表（13 类 × 100 条种子数据导入）、商家表、服务图片、服务搜索接口（分词 + 打分）、收藏、评分汇总、销量统计。
- 可配：分类（名称双语、图标、颜色、角标如"24H"、排序、是否在首页、上/下架）；Banner 列表（图片、文案双语、跳转目标、上下线时间、排序）；活动页选品规则；推荐位（featuredIds）；特惠阈值（< RM35）；热门搜索词；分页数（20）。

### 2.3 下单 / 支付 / 订单 / 售后（checkout.js）
- 功能：6 种流程（服务、商品、话费充值、咨询、求职投递、通用需求）；需求表单（各分类字段不同）；确认订单（数量、时段/日期时间、地址、优惠券自动选最优、5 种支付方式）；支付；下单成功；订单列表（6 种状态筛选）；订单详情与时间线；商家确认；取消与退款；确认完成；评价（星级 + 6 个标签 + 文字）；再来一单；购物车（按店铺分组、满额免运费、分组结算）；联系商家。
- 后端：**服务端计算价格**（不信任前端）、运费/服务费、优惠券校验核销、订单号生成、订单状态机、支付单与回调、钱包扣款、退款（原路或退钱包，可配）、后台任务推进订单状态、商家聊天消息、通知。
- 可配：费用表（超市配送 RM3.9 满50免 / 美食 RM4.5 满40免 / 鲜花 RM8 满150免 / 到家服务类服务费 RM2）；支付方式开关与排序；FPX 银行列表；配送时段；可预约时间（08:00–21:00，每 30 分钟）；最少提前下单（30 分钟）；数量上限（小时 12/件 99）；商家自动确认（10–20 秒，可设为"关闭，需商家/后台手动确认"）；商品确认后多久进入配送（30 秒）；取消原因（5 种）；临近服务不可取消时间（2 小时）及手续费；退款去向；评价标签；需要地址的分类。

### 2.4 钱包 / 充值 / 账单 / 提现
- 功能：余额、充值（6 个档位 + 自定义，4 种渠道）、账单列表（按天分组、分页、点击跳订单/聊天）；**提现目前前端没有**，按你的要求补做（银行卡/电子钱包提现申请 → 后台审核）。
- 后端：钱包账户 + **流水表（每一笔增减都有记录，余额只由流水驱动）**、充值订单与支付回调、提现申请与审核、对账。
- 可配：充值档位（20/50/100/200/500/1000）、单笔限额（RM1–5000）、充值渠道；提现最低金额、手续费、每日次数、审核方式；新用户初始余额（RM100）和金豆（1000）。

### 2.5 签到 / 任务 / 积分 / 优惠券 / 会员（flows.js）

- 可配：签到每日奖励（10）、第 7 天加奖（50）；任务列表与奖励（资料 20/发帖 10/地址 10）；优惠券模板（新人 RM10 满80 30天、会员 RM5 满50 30天、美食 RM5 满30 14天 限美食、秋日 RM15 满120）；新用户自动发放的券；会员权益文案。

### 2.6 社交：发现 / 动态 / 好友 / 群（catalog.js + flows.js）
- 功能：交友列表（推荐/附近，按城市+兴趣筛选）、个人主页、关注/取关、粉丝/访客/关注/收藏统计、动态（推荐/关注）、发帖（文字、图片、话题、地点、公开/私密）、点赞、评论、打招呼（3 条推荐语）、加好友（按 ID/手机号）、好友请求（接受/忽略）、联系人、群（我的/发现、详情、加入、退出、创建）、拉黑/解除、举报（7 种原因，可同时拉黑）、邀请好友（邀请码 SZ+ID）、个人二维码名片（`#u/<ID>` 公开页）。

- **现有 600 个虚构人物、600 条动态、120 个群、100 段会话**：导入数据库作为"运营账号/演示内容"，后台可管理（可隐藏/删除/编辑），与真实用户混排。

### 2.7 聊天（chat-tools.js）

### 2.9 直播 / 一对一视频（live-room.js / private-room.js）

## 3. 管理后台设计（/admin）

### 3.1 基础
- 独立登录（管理员账号与用户账号分开），可选二次验证。
- **角色权限（RBAC）**：超级管理员、运营、客服、财务、审核员、只读；菜单和按钮级权限。
- **操作日志**：所有后台修改留痕（谁、何时、改了什么、改前改后）。
- 中英双语界面，适配桌面与平板。
