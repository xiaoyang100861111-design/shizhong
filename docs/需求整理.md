## 2. 网页 + 安卓 + 苹果只维护一套系统：能做到

**方案：一套后端 + 一套前端 + Capacitor 打包 App。**

```
            ┌──────── 同一套 H5 前端代码（现有代码）────────┐
            │                 │                    │
        浏览器网页        安卓 App（Google Play）   苹果 App（App Store）
                          └── Capacitor 打包，调用原生能力 ──┘
            │                 │                    │
            └──────── 同一个 ASP.NET Core API + SQL Server ──┘
                              管理后台 /admin
```

- **为什么选 Capacitor**：现有前端是纯 H5（没有框架、没有构建），Capacitor 可以直接把它装进 App 壳，**不用重写**。以后改功能只改一处，网页和两个 App 同时更新。
  - 如果换 Flutter / React Native，就要把 2.4 万行前端全部重写，等于维护两套前端，不符合你"只维护一套"的要求。
- **App 里能用的原生能力**：推送通知、相机/相册、麦克风、定位、分享、扫码、生物识别登录、深链。
- **本期要为 App 做的准备**（写后端时一起做，避免以后返工）：
  1. 登录同时支持 Cookie（网页）和 Token（App）。
  2. 接口地址可配置（App 里不是同域）。
  3. 推送通知预留设备 Token 表。
  4. 后台可配"App 最低版本 / 强制更新提示"。
- **上架的硬性规定（很重要，影响设计）**：
  - 苹果和谷歌都要求：**App 里购买虚拟物品（金豆、礼物、VIP、装扮）必须走它们的内购**，平台抽成 15%–30%。
    - 实物商品和线下服务（保洁、外卖、鲜花、接机）**可以**用自己的支付。
    - 所以金豆充值要预留"内购"渠道，后台可按平台（网页 / 安卓 / 苹果）配置不同的充值包价格。
  - 苹果要求 App 必须提供**App 内注销账号**（原型里已有"删除账号"，会做成真实功能）。
  - 有用户发布内容和聊天的 App，必须有**举报、拉黑、内容审核**（已在需求里）。
  - 直播、一对一视频类 App 审核较严，需要年龄限制（原型已有"年满 18"勾选）和内容审核机制。
- **App 打包本身不在本期**：本期先把后端和网页做完，并在前端预留好 Capacitor 接入点。打包和上架需要苹果开发者账号（USD 99/年）和谷歌开发者账号（USD 25 一次性）。

## 3. 总体架构

- 服务端同时托管：用户端网页 `/`、管理后台 `/admin`、用户接口 `/api/*`、后台接口 `/api/admin/*`、实时通道 `/hubs/*`。
- 后台任务：订单自动流转、红包 24 小时退回、优惠券过期、通知推送、统计汇总。
- **所有写死的参数 → 配置表**，前端启动时拉取；后台改完立即生效，每项都有"恢复默认"。
- 金额按"分"存 BIGINT，金豆 BIGINT，时间 UTC，文本 NVARCHAR（支持中文）。
- **钱包和金豆余额只由流水驱动**：每一笔增减都有流水记录，余额可对账。
- 保留"离线演示模式"：双击 `index.html` 打开时，前端仍按原型的本地模拟运行。

- **本期**：
  - 手机号 + 密码注册，邮箱 + 密码注册，任选一种；两种登录方式都支持。

  - 体验账号保留（后台可关闭）。
- **【本期占位】**：
  - 短信/邮件验证码、忘记密码的自助找回、Google/Apple/Facebook 登录。这些按钮先隐藏，后台有开关。
  - 忘记密码暂时由后台客服重置。
- **后端**：用户表、BCrypt 密码、会话 Token、登录失败锁定、唯一 8 位用户 ID、同意条款记录、登录日志。
- **可配**：
  - 密码规则（8–64 位含字母数字）、登录失败锁定（5 次 / 30 秒）。
  - 昵称长度（20）、国家区号列表（16 个）。
  - 注册城市（吉隆坡、八打灵再也、槟城、新山、马六甲、怡保）、兴趣标签（14 个）。

## 8. 还需要你核对的事项

1. **礼物价格统一（重要）**：原型的礼物商城用 **RM** 标价，而且价格偏高（城堡 RM200,000、火箭 RM185,000）；直播间用**金豆**标价。两套价格互相矛盾。
   - 我的建议：**所有礼物统一用金豆标价**（按 RM1 = 10 金豆，商城城堡 = 20,000 豆 ≈ RM2,000），商城和直播共用一个价。
   - 这也符合苹果和谷歌的内购规定：虚拟物品只用金豆买，金豆通过内购或网页充值获得。
   - 这会改变原型商城的扣款方式（从扣 RM 余额改为扣金豆）。同意吗？
2. **本期没有在线支付，钱怎么进钱包**：本期余额只能靠后台手动调账（用户线下转账后，财务在后台入账）。这样可以吗？
3. **一对一视频**：没有音视频服务商前，一对一入口是先**隐藏**，还是保留成"演示模式"（界面能走通、计费照常，但没有真实画面）？我建议隐藏，避免真实扣费却没有服务。
4. **注册方式**：手机号 + 密码、邮箱 + 密码都开放？没有验证码意味着任何人都能用别人的手机号注册，建议以后接短信后再强制验证。本期先这样可以吗？
5. **服务器信息**（部署时需要，现在不急）：
   - Windows Server 版本。
   - 是否已装 .NET 8 Hosting Bundle，IIS 是否开启 WebSocket（实时聊天需要）。
   - **域名和 HTTPS 证书**：App 上架、语音录制、分享都要求 HTTPS。
6. **管理后台初始管理员**：账号名用什么？首次登录强制改密码。
7. **语言**：本期界面保持简体中文 + 英文（原型已有），马来语以后加。可以吗？
8. **安全**：`sa` 密码已在聊天里出现过。上线前请修改；程序改用专用低权限账号（我会在建库脚本里附上创建语句）。
