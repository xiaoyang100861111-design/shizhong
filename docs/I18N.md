# 适中 Shizhong — Translation guide

Languages today: 简体中文 (`zh-CN`, source) and English (`en`). The system is built so that a new
language is **one file plus one command**.

## Add a language (e.g. Bahasa Melayu)

```bash
node tools/i18n.js scaffold ms "Bahasa Melayu" ms-MY   # creates locales/ms.js (English text as a start)
                                                       # and adds its <script> tag to index.html
node tools/i18n.js export ms > ms.csv                  # key, zh-CN, en, ms — give to a translator
node tools/i18n.js import ms ms.csv                    # write translations back
node tools/i18n.js check                               # missing keys / placeholder mismatches
```
The language immediately appears in Settings › Language and on the welcome screen. Untranslated
keys fall back to English (the new locale's `fallback`), then Chinese. Demo content (service
names, bios, posts) can optionally be translated too — see "Content" below; without it the
original text is shown.

## Using translations in code

```js
t('catalog.detail.book')                         // plain string
t('order.placed', { id: order.id })              // params in {braces}
tn('catalog.count', items.length)                // plurals: { one: '{n} service', other: '{n} services' }
td('city', service.city)                         // enumerated data value stored in Chinese
tc('services', s.id, 'name', s.name)             // translated demo content, falls back to original
SZ.fmt.money(12.5) / SZ.fmt.dateTime(ts)         // never hand-format numbers or dates
```

* `t()` does **not** escape. In HTML templates escape user/demo data params:
  `t('chat.sentGift', { name: esc(person.name) })`. Message text itself is trusted.
* No Chinese (or any UI language) string literals in JS/HTML templates. Data files are the only
  place source-language text lives. Values that are stored and compared (order status, filter
  ids) stay as stable ids; only the label is translated.
* Keys: `<owner>.<area>.<name>`, lowerCamelCase, e.g. `live.gift.send`, `flows.wallet.title`.
  Reuse `common.*` for OK/Cancel/Save/Back/etc. Accessibility labels need keys too.
* Don't build sentences from pieces (`t('a') + name + t('b')`); use one key with params — word
  order differs between languages.
* Leave room: English is often 30–60% longer than Chinese.

## Locale file layout

`locales/<code>.js` → `SZ_I18N.register(meta, messages)`.
`meta`: `code`, `name` (native, shown in the picker), `englishName`, `htmlLang`, `intl` (Intl
locale for numbers/dates, e.g. `en-MY`), `dir` (`ltr`/`rtl`), `order`, `fallback`, `content`
(list of demo-content chunks shipped for this language, see below).

`messages` top level: `common`, `nav`, `time`, `storage`, `boot` (core) and one block per owner
module (`shell`, `flows`, `catalog`, `gifts`, `live`, `private`, `chat`, `vip`, `regions`,
`auth`), then `data` — translations of enumerated values keyed by the source text:
`data: { city: { 吉隆坡: 'Kuala Lumpur' }, live: { topic: { 同城聊天: 'Local chat' } } }`
used through `td('city', value)` / `td('live.topic', value)`.

## Content (demo data) translations

Large demo datasets are translated separately so the UI files stay small:
`data/i18n/<code>/<chunk>.js` calls
`SZ_I18N.addContent('<code>', '<kind>', { '<id>': { name: '…', bio: '…' } })`.
List the chunk names in the locale meta `content: [...]`; the loader fetches the overlay together
with the base chunk. Read with `tc(kind, id, field, original)` or the app.js shortcuts
`lc(kind, record, field)` and `personName(person)` (romanised names in English).

Content kinds: `services` (name, sub, store, area, sales, badge, unit), `orders` (title), `people`
(name, area, occupation, bio, tags[], language, activeText, theme, room), `profiles` (about, schedule,
callTopics[], roomComments[], friendMessage), `posts` (text, topic, place, comments[]), `groups` (name,
desc, area, topic, rules[], meetup, messages[]), `conversations` (messages[] by index, keyed by person id).
Pipeline for new languages: `tools/l10n/extract.js <code>` → translate → `tools/l10n/terms.js` → `tools/l10n/assemble.js`.

## Switching language at runtime

`SZ_I18N.setLocale(code)` stores the choice (`localStorage['sz:locale']`) and reloads, so every
screen re-renders consistently. First visit picks the browser language when available.
