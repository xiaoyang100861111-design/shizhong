# 性能优化报告（图片 WebP 化、压缩、缓存、字体统一）

日期：2026-09-29 · 分支 claude/tender-ritchie-jw0yfm 之上

## 1. 测量方法

- 工具：`node tools/perf/measure.js --base http://127.0.0.1:5094 --runs 3 --account demo|guest`（Playwright + Chrome DevTools Protocol）。
- 条件：Lighthouse 手机预设的慢速 4G（RTT 150 ms、下行 1.6 Mbps、上行 750 kbps），CPU 降速 4 倍，390×844、DPR 3。
- 每次运行都是全新浏览器上下文（冷缓存）：打开首页 → 记录 FCP / LCP / 长任务 / 每个请求的传输字节 →
  依次点底部标签（发现、直播、消息、我的、首页）→ 最后刷新一次（热缓存）。表中为 3 次的中位数。
- 服务端：本地 Kestrel（HTTP/1.1，同一台机器），开发库 `shizhong`。生产环境经 Cloudflare 走 HTTP/2/3，请求数的影响会更小，字节数的结论不变。
- demo = 演示账号（登录后的完整首页和状态）；guest = 首次访问的游客（欢迎页）。

## 3. 做了什么

### 图片

- **`tools/perf/optimize_images.py`**（可重复运行、幂等）：把 `assets/` 下 688 个 JPG/PNG 转成同名 `.webp`：
  照片有损 q80；带透明的图形在无损和 q85 中取小者；调色板图和小图（国旗）优先无损；动态 PNG 头像转动态 WebP；
  `assets/oriental`、`assets/live-gifts`（礼物素材的原始稿）无损转换，`assets/gift-art/_tools/build_raster.py` 已能读取 WebP。
- **小尺寸副本**：`assets/photos/*`、`assets/optimized/*` 各生成 `<名>.w320.webp`（320 px 宽）。
  `thumbAsset()` 给头像、缩略图（≤ 100 CSS px）用小图；`srcsetAttr()` 给照片输出 `srcset`（320w / 640w）+ `sizes`
  （商品卡片 `(min-width: 480px) 240px, 50vw`）。
- **所有引用已改写**：代码、CSS、HTML、数据块、礼物清单、后台 Vue、QA 场景、服务端种子与人设 C#（共 1 678 处，44 个文件），
  以及运行时拼接的名字（`'flags/' + code + '.webp'`、`'animated-avatars/' + id + '.webp'`、种子里的 `*.webp` 目录枚举）。
- **原图已删除**（git 历史中保留）。根目录的原始大图 `hero.png`（2 MB）、`logo.png` 等 15 个"别名"原稿也删除，
  它们一直通过 `window.SHIZHONG_ASSETS` 指向 `assets/optimized/`。
- **数据库迁移 `0903_webp_images.sql`**：把已存储的图片路径改为 `.webp`（Users.Avatar、Posts/Services/Orders/OrderItems/
  Banners/Categories/GiftBackgrounds.Image、LiveSessions.Cover、Gifts.ArtFull/ArtThumb/ArtCharm；这些列由扫描开发库全部文本列得出）。
  先在 `shizhong` 的备份还原副本上验证（447 个不同路径全部对应到存在的文件），再随 API 启动应用到 `shizhong`。
- **兼容旧版本**：`Site.cs` 在 `.jpg/.png` 文件不存在时返回同名 `.webp`（反之亦然）——旧 App、CDN 缓存、未迁移的数据都不会 404。
  前端 `asset()` 把本地 `.jpg/.png` 名直接请求为 `.webp`；若 `.webp` 不存在（新加但尚未转换的图），`<img>` 自动按原名重试一次。
- **懒加载**：列表图片 `loading="lazy" decoding="async"`（商品/帖子卡片原已如此，补上直播间、私密通话的列表）；
  首页多张横幅只有第一张 `fetchpriority="high"`、其余懒加载；卡片使用 `aspect-ratio` 盒子，CLS 为 0。
- **上传**：`SZ.media.compress` 在浏览器能编码 WebP 时（Chrome、Android WebView）输出 WebP（保留 PNG 透明），
  Safari 仍为 JPEG；重新编码不变小时保留原文件。聊天相册、视频、Range 流测试全部通过。
  服务端 MediaStore **没有**加转码：.NET 没有内置 WebP 编码器，需要 SkiaSharp/ImageSharp 等原生库或商业许可，
  发布包会增加十几 MB，不属于"便宜且安全"。

### 压缩与缓存

- **Brotli / gzip 改为 Optimal**：原来的 Brotli 默认级别（Fastest）比 gzip 还大——`catalog.js` 52 KB（gzip 46 KB），
  `/core/server.js` 298 KB（gzip 138 KB）。改后分别为 38 KB、126 KB；`data/catalog-index.js` 208 → 80 KB。
  这一项是脚本体积下降的主因，单次压缩耗时几毫秒。
- `/data/*.js`（数据库生成）：`private, no-cache` + ETag，未变时 304。
- 静态文件：HTML `no-cache`；带 `?v=` 的 JS/CSS/图片 `public, max-age=31536000, immutable`（版本号随每次发布变化，更新一定能到达）；
  不带版本号的 `/assets/*` 为一天 + `stale-while-revalidate` 一周；其它一小时。Cloudflare 按"遵循现有标头"即可。
- `web.config`（build_server.py）：`.webp`、`.avif`、`.svg`、`.webmanifest` 的 MIME；关闭 IIS 自身压缩（应用已做 Brotli/gzip，图片本身已压缩）。
  `Site.cs` 也显式登记了 `image/webp`、`image/avif`。

### 没有做的（测量后的判断）

- **AVIF**：WebP 已把图片降到 392 KB，首屏瓶颈已转到脚本；AVIF 需要 `<picture>` 双份文件和更慢的编码，收益不明显。
- **Service Worker**：带版本号的资源已被 HTTP 缓存 immutable 缓存，数据块有 ETag；SW 额外收益很小，
  却要承担在服务器模式下缓存到旧接口数据的风险，因此不加。
- **preconnect / preload**：页面没有第三方域名；首屏 LCP 图片来自数据库横幅，HTML 中无法预知，预加载反而可能浪费流量。
- **脚本拆分**：43 个脚本均已 `defer`，数据块（people、posts、services-*）已按需加载。LCP 现在主要受两项限制：
  1. `/core/server.js` 启动数据：演示账号 863 KB 原文（Brotli 后 126 KB），其中 `state.messages` 约 324 KB、`state.orders` 129 KB；
     建议由消息 / 订单模块改为首屏只带最近若干条、其余按需拉取。
  2. 所有功能脚本在启动时执行（直播间、私密通话、VIP、礼物等约 250 KB 压缩后）；改为进入功能时再加载需要各模块配合。
  两项都涉及其它模块的数据结构，本次只记录数据，不改动。

## 4. 字体

- `core/tokens.css` 定义唯一的字体系统（不加载任何网络字体，首屏无需等待字体下载）：
  - `--font-sans`：`-apple-system, BlinkMacSystemFont, "PingFang SC", "Hiragino Sans GB", "Microsoft YaHei", "Noto Sans SC", "Noto Sans CJK SC", "Helvetica Neue", Arial, sans-serif`
  - `--font-num`（金额、数量、时间，配合 `font-variant-numeric: tabular-nums`）：系统拉丁 UI 字体在前（SF / Segoe UI / Roboto 的数字），
    后面是同样的中文字体。原来的 `--font-num` 没有中文字体，"RM 12 起"里的"起"在 Windows 上会落到宋体。
  - `--font-mono`：`ui-monospace, "SF Mono", SFMono-Regular, Menlo, Consolas, "Liberation Mono", "Roboto Mono", monospace`
  - `--font-display-serif`：仅用于装饰。
- 已替换的零散字体栈：vip-entry.css（2 处）、finance.css、flows.css、chat-tools.css（2 处）、chat-tg.css（8 处）、
  personal-qr.js 的 canvas 文字（5 处，读取 `--font-sans`）、后台 `styles.css`（并设置 Element Plus 的 `--el-font-family`）及 10 个 Vue 文件的等宽字体、Capacitor 的离线提示页。
  修正 oriental-effects.css 中无效的 `font: 500 13px/1 inherit`（整条声明原本被浏览器丢弃）。
- **保留的装饰字体**：`oriental-effects.css` 的东方礼物特效——大字"福"类徽记和礼物名称用 `--font-display-serif`
  （Georgia、宋体 Songti SC / STSong / Noto Serif CJK SC / SimSun），这是有意的书法 / 宋体效果。
- `assets/gift-art/_review/*.html` 是内部审图页，未改。

## 5. 以后怎么用

```bash
pip install pillow
python3 tools/perf/optimize_images.py            # 转换新图片、生成 w320 副本、改写引用、删除原图
python3 tools/perf/optimize_images.py --dry-run  # 只看会改什么
python3 tools/perf/optimize_images.py --check    # CI：有未转换的图片、过期引用或指向不存在图片的引用时退出码 1
python3 tools/perf/optimize_images.py --keep-originals   # 转换并改写，但保留 .jpg/.png
```

- 合并其它分支后直接再运行一次：它只转换没有最新 `.webp` 的图片，只改写 `.webp` 已存在的引用，没事可做时什么也不改。
- 不会修改已执行过的迁移（`server/db/migrations`）和 `docs/`。数据库里新出现的旧路径由 `Site.cs` 的回退兜底。
- 输出末尾的"Check by hand"列出运行时拼接图片名的代码（如 `Directory.GetFiles(dir, "*.jpg")`），需要人工确认。
- 测量：`node tools/perf/measure.js --base <地址> --runs 3 --account demo`；
  QA 时收集失败图片请求：`node -r ./tools/perf/image_watch.js tools/qa/app_server_walk.js --base <地址>`（任何 Playwright 脚本都可以）。
  `tools/qa/smoke.py` 现在也把失败的图片请求记为错误。
